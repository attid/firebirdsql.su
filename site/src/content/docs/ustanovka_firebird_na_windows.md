# Установка Firebird на Windows

Ставить Firebird под Windows просто: один инсталлятор, десять минут, и сервер уже работает как служба. Но есть пара мест, где новички спотыкаются, — про них ниже тоже расскажем. Эта инструкция для тех, кто ставит сервер впервые и хочет получить рабочий экземпляр без сюрпризов.

## Что понадобится

- Инсталлятор с официального сайта: [firebirdsql.org](https://firebirdsql.org/), раздел **en/downloads**. Актуальная ветка — **5.0.x**.
- Разрядность: **x64** для современных систем, **x86** — только если клиентские приложения 32-битные и это принципиально. Для сервера почти всегда берите x64.
- Права администратора на машине.
- Свободный порт **3050/TCP** — проверим это в разделе про грабли.

## Пошаговая установка

1. Скачайте инсталлятор и запустите его от имени администратора.
2. Мастер предложит выбрать компоненты: сервер, клиентская библиотека, инструменты разработчика, документация. Для сервера оставьте всё по умолчанию — лишним не будет.
3. Если сервер на этой машине не нужен, а надо лишь подключаться к удалённому, выберите вариант **Client only** — поставится только клиентская библиотека.
4. Задайте пароль **SYSDBA** — главного администратора базы. Не оставляйте его пустым и не используйте masterkey «для проверки»: это первое, что перебирают боты.
5. Завершите мастер. Сервер установится как служба Windows **Firebird Server** с автоматическим запуском — после перезагрузки поднимется сам.

## Проверка, что сервер жив

Откройте `services.msc` и найдите службу **Firebird Server** — она должна быть в состоянии «Выполняется».

Затем проверьте подключение через консольный клиент isql (идёт в комплекте):

```
isql localhost/3050:employee -user sysdba -password ваш_пароль
```

Если видите приглашение `SQL>` — всё работает, демонстрационная база employee отвечает. Вместо isql можно подключиться любым GUI-клиентом: хост `localhost`, порт `3050`, логин `sysdba`.

## Типичные грабли

| Симптом | Причина | Что делать |
|---------|---------|-----------|
| Служба не стартует или не принимает подключения | Порт 3050 уже занят вторым экземпляром Firebird или InterBase | Найдите, кто занял порт (`netstat -ano | findstr :3050`), снесите/перенастройте конфликтующий сервер |
| Приложение не видит сервер | Несовпадение разрядности: 32-битному клиенту нужна x86-библиотека fbclient | Поставьте клиент нужной разрядности рядом с приложением |
| Ошибки доступа при установке/запуске | Недостаточно прав в Program Files | Запускайте инсталлятор от администратора, не храните базы в Program Files |
| Локально работает, по сети — нет | Firewall не пропускает 3050/TCP | Откройте порт 3050 в брандмауэре Windows на сервере |

## Embedded-вариант

Если сервер как служба не нужен вовсе — например, база живёт внутри одного приложения, — есть **embedded**: это не инсталлятор, а отдельный zip. Распаковываете, кладёте библиотеку рядом с приложением — и оно работает с файлом базы напрямую, без установленного сервера. Удобно для portable-программ и тестов, но для многопользовательского доступа по сети нужен полноценный сервер.

## Что дальше

Первым делом после установки настройте **резервное копирование через gbak** — до того, как в базе появятся данные, которые жалко потерять. Ненастроенный бэкап — это то, о чём вспоминают в самый неподходящий момент.
