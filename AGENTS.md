# AGENTS.md — правила работы с репозиторием firebirdsql.su

## Что это за проект

Перенос сайта https://firebirdsql.su (русскоязычный справочник и FAQ по СУБД
Firebird, ~215 страниц) с DokuWiki на статический сайт в git и дальнейшее
развитие сайта. Правки контента от сообщества — через pull request.

Текущий этап и план работ: [ROADMAP.md](ROADMAP.md).

## Карта репозитория

| Путь | Назначение | Правила |
|------|-----------|---------|
| `legacy/` | Дамп старой вики: raw-разметка, `pages.json`, медиа | Только читать. Не редактировать, не удалять. Переснимается скриптом |
| `tools/` | Скрипты миграции (скрейпер, конвертер) | Менять по необходимости |
| `site/` | Новый сайт на Astro | Основная работа начиная с этапа 1 |
| `deploy/` | nginx, карта редиректов, инструкции деплоя | Обновлять при любом изменении URL |
| `docs/` | План миграции, SEO-стратегия, ADR | Обновлять при изменении решений |

## Контентная модель

Frontmatter каждой страницы: заголовок, раздел (глоссарий/FAQ/SQL-рецепты/
утилиты), тип страницы, поля версий Firebird `since/until/deprecated`
(ADR-0005; могут быть пустыми, но удалять их из схемы нельзя — на них
рассчитаны фильтр версий и будущий ИИ/RAG, ADR-0007). Структура страницы —
заголовки/блоки без экзотики, чтобы чанковалось без переделок.

## Жёсткие правила

1. **SEO прежде всего.** Запрещено менять или удалять URL страниц, не добавив
   запись в карту редиректов (`deploy/redirects.map`) и не обновив sitemap.
   После запуска нового сайта ни один старый URL (обе формы: `/doku.php?id=...`
   и `/<page_id>` с двоеточиями) не имеет права отдавать 404 — только 301.
2. **Лицензия.** Контент вики — CC BY-NC-SA 4.0: сохранять атрибуцию авторов
   (страница «Источники и Авторы»), не убирать указание лицензии.
3. **Язык.** Контент сайта — русский. Код, имена файлов, коммиты — английский.
4. **Источник контента.** `legacy/` — неизменяемый снимок для миграции.
   Рабочий контент живёт в `site/src/content/` после конвертации; правки
   контента — только там.
   **Жизненный цикл конвертера:** до переключения на новый сайт MD в
   `site/src/content/docs/` — сгенерированный артефакт, руками НЕ править
   (конвертер перезаписывает файлы целиком). После переключения конвертер
   заморожен навсегда; запускать его на рабочем контенте запрещено —
   `site/src/content/docs/` становится единственным источником истины,
   новые страницы добавляются в том же формате (frontmatter-схема
   обязательна, билд её валидирует).
5. **Git.** Коммит — только по явной просьбе владельца. `git push` — никогда
   без явной команды владельца.
6. **Нетривиальная работа с кодом** — сначала карта кодовой базы (скилл
   codespaces из OpenViking: build → query → правки). Репо маленькое, карта
   строится за секунды.
7. **Деплой на прод** — только по явной команде владельца и только после
   smoke-теста карты редиректов по всему `legacy/pages.json`.

## Факты о старом сайте (источник — разведка 2026-09-23)

- Движок: DokuWiki, PHP 8.4.16, nginx, HTTP/2. Домен firebirdsql.su, HTTPS.
- Хостинг: Docker на сервере владельца; новый сайт тоже разворачивается
  в Docker на этом же сервере (ADR-0002).
- Стек нового сайта: Astro + Pagefind, контент в Markdown (ADR-0003),
  первый проход миграции 1:1 (ADR-0004).
- Аналитика: Яндекс.Метрика, счётчик 25113035.
- URL: две рабочие формы — `/doku.php?id=<page_id>` и `/<page_id>`.
  Обе отдают 200, обе нужно покрыть редиректами. Все 249 страниц лежат
  в корневом пространстве имён (вложенности нет), ID латиницей.
- Raw-текст страниц доступен анонимно: `doku.php?do=export_raw&id=<page_id>`.
  Несуществующая страница возвращает HTML вместо raw — так скрейпер
  детектирует битые.
- Известные проблемы старого сайта: robots.txt и sitemap.xml отсутствуют
  (запросы к ним отдают 200 со страницей «не существует» — soft-404);
  canonical в HTML указывает на `http://`; часть проиндексированных страниц
  уже мертва (пример: `glossarij:coalesce`).

## Команды

```bash
# Снять/обновить дамп старой вики (идемпотентно, пропускает уже скачанное)
python3 tools/scrape_dokuwiki.py

# Конвертация дампа в Markdown (появится на этапе 1)
python3 tools/convert_dokuwiki.py

# Сборка нового сайта (появится на этапе 1)
cd site && npm install && npm run build
```
