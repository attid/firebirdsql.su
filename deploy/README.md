# deploy/ — развёртывание

Этап 2 (см. ROADMAP.md). Здесь появятся:

- `Dockerfile` — nginx + собранная статика (`site/dist/`);
- `docker-compose.yml` — сервисы нового сайта на том же сервере;
- `nginx.conf` + `redirects.map` — карта 301 со всех старых URL (обе формы:
  `/doku.php?id=...` и `/<page_id>`), генерируется `tools/make_redirect_map.py`
  из `legacy/pages.json`;
- инструкция по переключению и откату на старый контейнер вики.

## Сервисы compose

1. **site** — nginx + статика + карта 301 (основной).
2. **remark42** — комментарии, авторизация Telegram + Яндекс + Google
   (ADR-0006): `AUTH_TELEGRAM` + токен бота от @BotFather, `AUTH_YANDEX` +
   ключи приложения Яндекс.OAuth, `AUTH_GOOGLE` + OAuth-клиент Google Cloud
   Console; данные в volume `remark42-data`. Прочие провайдеры (GitHub,
   Apple, email, аноним) — по желанию позже.
3. **ai** — закомментированный слот под будущий ИИ-сервис (ADR-0007);
   включается без перестройки топологии.

## Защита (DDoS / злоупотребления)

- nginx `limit_req` зоны: `/api/remark/*` (строгая) и будущий `/api/ai/*`
  (строже: токены денег стоят) — закладываются в конфиг этапа 2 сразу;
- штатные лимиты remark42 (частота и размер сообщений, edit window);
- таймауты и ограничение тела запроса на проксируемых location;
- кэш ответов типовых вопросов для ИИ-эндпоинта — на этапе включения;
- вариант усиления при необходимости — Cloudflare-прокси перед сервером
  (решение владельца, базовая защита и без него обязательна).

Жёсткое правило: карта редиректов обновляется только регенерацией из
`pages.json`, руками не редактируется. Перед каждым деплоем — smoke-тест
редиректов по всему списку старых URL.
