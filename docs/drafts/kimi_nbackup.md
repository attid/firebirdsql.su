# nbackup: быстрое резервное копирование Firebird

Если ваша база Firebird весит десятки гигабайт и gbak молотит её часами — эта статья для вас. **nbackup** — штатная утилита физического бэкапа, которая входит в поставку Firebird с версии 2.1. В отличие от gbak она работает на уровне страниц базы и делает **мгновенный снапшот**: база при этом продолжает обслуживать пользователей.

## Чем nbackup отличается от gbak

gbak — логический бэкап: он выгружает данные постранично, читая их через API сервера, и собирает результат в сжатый файл `.fbk`. Надёжно, но долго. nbackup просто копирует страницы файла базы, а все изменения во время копирования пишет во временный файл дельты (`.delta`).

| Критерий | gbak | nbackup |
|---|---|---|
| Тип бэкапа | Логический (выгрузка данных) | Физический (копия страниц) |
| Скорость | Медленно на больших базах | Мгновенный снапшот |
| База во время бэкапа | Работает | Работает |
| Проверка целостности | Да | Нет |
| Сжатие результата | Да (`.fbk`) | Нет |
| Перенос между версиями/платформами | Да | Нет |
| Инкрементные копии | Нет | Да (уровни 0–8) |

## Команды

nbackup поддерживает уровни бэкапа: `-B 0` — полная копия, `-B 1..8` — инкремент от предыдущего уровня.

```
nbackup -B 0 база              — полный бэкап уровня 0 (быстрый снапшот)
nbackup -B 1 база backup1.nbk  — инкрементный уровень 1
nbackup -R база backup0.nbk backup1.nbk  — восстановление (слить дельты)
nbackup -F база                — фиксация дельты (после успешного копирования файла базы вручную)
```

Разница между уровнями хранится через временные файлы дельт (`.delta`), поэтому уровни должны идти строго по порядку: нельзя восстановить уровень 2, не имея 0 и 1.

## Восстановление

Восстановление — это слияние дельт:

```
nbackup -R база backup0.nbk backup1.nbk
```

Результат — обычная копия страниц базы, а **не** `.fbk`! Просто переименуйте файл в `.fdb` и запустите сервер. Никакого длительного процесса восстановления, как у gbak, не требуется — это ещё одно преимущество: RTO (время восстановления) минимально.

## Стратегия: комбинируем nbackup и gbak

Это не «или–или», а «и–и»:

- **nbackup каждый час** — быстрые точки восстановления без нагрузки на пользователей;
- **gbak раз в сутки** (например, ночью) — логическая проверка целостности, сжатый архив, страховка для переноса на другую версию сервера.

Для маленькой базы (пара гигабайт) хватает одного gbak. Для большой базы в режиме 24/7 связка выше — стандарт де-факто.

## Грабли

| Проблема | Что делать |
|---|---|
| Файл снапшота скопировали «потом» | Копируйте сразу: дельта продолжает писаться и растёт |
| Пропустили уровень при восстановлении | Восстановление требует те же уровни по порядку — храните всю цепочку |
| База уже испорчена, nbackup «не помог» | nbackup — не проверка целостности, он честно скопирует битые страницы. Проверяйте базу gbak/gfix отдельно |
| Баги с блокировками на Firebird 2.5 | Используйте свежие версии — там эти проблемы исправлены |

Отдельно помните про `nbackup -F база`: если копировали файл базы вручную, после успешного копирования зафиксируйте дельту, иначе изменения так и будут копиться в `.delta`.
