# Триггеры в Firebird: типы, события, NEW и OLD

## Что такое триггер и когда он нужен

Триггер — хранимый блок PSQL-кода, который выполняется автоматически при
наступлении события: изменении данных в таблице или представлении, событии
уровня базы данных или DDL-операции. Типичные задачи: аудит изменений,
проверка бизнес-правил, вычисление производных значений, каскадные правки,
журналирование подключений. Триггеры существуют во всех версиях Firebird
(2.5–6.0); отличается лишь набор доступных типов событий.

## DML-триггеры: события, NEW и OLD

DML-триггер привязывается к таблице или обновляемому представлению и
срабатывает на INSERT, UPDATE или DELETE в фазе BEFORE (до операции) или
AFTER (после неё). На одно событие можно объявить несколько триггеров —
порядок их выполнения задаётся предложением POSITION. Один триггер может
обрабатывать несколько событий, перечисленных через OR:

```sql
CREATE TRIGGER trg_biud FOR my_table
BEFORE INSERT OR UPDATE OR DELETE AS ...
```

Мультисобытийные триггеры поддерживаются начиная с Firebird 1.5, то есть во
всех версиях диапазона 2.5–6.0.

Внутри DML-триггера доступны контекстные переменные NEW и OLD: для UPDATE
NEW — новое значение столбца, OLD — прежнее. В INSERT контекст OLD
недоступен, в DELETE — NEW. В BEFORE-триггере значения NEW.xxx можно
изменять, тем самым корректируя вставляемые или обновляемые данные. Для
различения событий внутри мультисобытийного триггера служат контексты
времени INSERTING, UPDATING и DELETING.

Пример — аудит-триггер на UPDATE, фиксирующий изменение зарплаты:

```sql
CREATE TRIGGER trg_emp_audit FOR employees
AFTER UPDATE AS
BEGIN
  IF (OLD.salary IS DISTINCT FROM NEW.salary) THEN
    INSERT INTO salary_log (emp_id, old_salary, new_salary, changed_at)
    VALUES (OLD.id, OLD.salary, NEW.salary, CURRENT_TIMESTAMP);
END
```

## Триггеры событий базы данных

С Firebird 2.1 доступны триггеры на события уровня базы: ON CONNECT,
ON DISCONNECT, ON TRANSACTION START, ON TRANSACTION COMMIT и
ON TRANSACTION ROLLBACK. Они подходят для журналирования подключений,
контроля сеансов и действий при фиксации или откате транзакций.

## DDL-триггеры

С Firebird 3.0 появились DDL-триггеры, срабатывающие в фазе BEFORE или
AFTER на выполнение DDL-операторов. Они позволяют отслеживать или
ограничивать изменения метаданных базы.

## Ограничения и грабли

- Операторы управления транзакциями (COMMIT, ROLLBACK) в PSQL недопустимы:
  это нарушило бы атомарность оператора, вызвавшего триггер. Исключение —
  блок IN AUTONOMOUS TRANSACTION (с Firebird 2.5), выполняющийся в отдельной
  автономной транзакции.
- Внутри триггера можно бросать исключения (EXCEPTION), вызывать хранимые
  процедуры и изменять NEW.xxx. Неперехваченное исключение прерывает
  операцию, вызвавшую триггер.
- Изменять NEW.xxx осмысленно только в BEFORE-триггерах: в AFTER-фазе
  данные уже записаны.
- Триггеры могут быть определены и для представлений — так реализуются
  обновляемые представления (updatable views).
- Информация о триггерах хранится в системной таблице RDB$TRIGGERS, тексты
  сообщений об ошибках — в RDB$TRIGGER_MESSAGES.

## Какие бывают триггеры

| Тип | Версии | События |
|---|---|---|
| DML (таблицы и представления) | все (2.5–6.0) | BEFORE/AFTER INSERT, UPDATE, DELETE; несколько событий через OR |
| События базы данных | 2.1+ | ON CONNECT, ON DISCONNECT, ON TRANSACTION START, ON TRANSACTION COMMIT, ON TRANSACTION ROLLBACK |
| DDL | 3.0+ | BEFORE/AFTER DDL |
