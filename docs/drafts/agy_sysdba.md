# SYSDBA в Firebird: пароль по умолчанию и смена

При администрировании СУБД Firebird одной из первых задач становится настройка учётной записи главного администратора. В этой статье рассмотрены особенности учётной записи SYSDBA, стандартные пароли в разных ОС, синтаксис смены пароля в современных и устаревших версиях, а также нюансы работы плагинов безопасности.

## Кто такой SYSDBA

**SYSDBA** (*System Database Administrator*) — это встроенный суперпользователь СУБД Firebird, существующий во всех версиях от 2.5 до 6.0. Он обладает неограниченными привилегиями: может создавать, изменять, удалять базы данных, управлять пользователями и правами доступа.

Важно помнить: SYSDBA — это именно **пользователь**, а не роль. Его нельзя путать с системной ролью `RDB$ADMIN`, которая предоставляет расширенные административные права обычным пользователям внутри конкретной базы данных.

## Пароль по умолчанию и особенности его генерации

Исторически стандартным паролем суперпользователя в Firebird является **`masterkey`**.

С этим паролем связаны ключевые технические нюансы:
* **Ограничение длины в 8 символов (DES/Legacy).** В устаревшем механизме аутентификации значимы только первые 8 символов. Поэтому пароль `masterke` считается идентичным `masterkey`.
* **Установка на Windows.** Официальный инсталлятор для Windows запрашивает пароль SYSDBA во время установки. Если СУБД устанавливается поверх существующей копии, старый пароль может сохраниться без перезаписи.
* **Установка на Linux.** При установке из tarball-архива инсталляционный скрипт автоматически генерирует случайный пароль и сохраняет его в текстовом файле `SYSDBA.password` (располагается в корне каталога установки, например `/opt/firebird/SYSDBA.password`, либо в `/etc/firebird/`).

## Как сменить пароль SYSDBA

Способ изменения пароля зависит от используемой ветки Firebird.

### Firebird 3.0 и новее (SQL-синтаксис)

Начиная с Firebird 3.0, управление учётными записями осуществляется штатными SQL-командами через любую утилиту выполнения запросов (например, `isql`):

```sql
ALTER USER SYSDBA SET PASSWORD 'НовыйПароль';
```

Если требуется задать пароль в конкретном плагине аутентификации, используется директива `USING PLUGIN`:

```sql
ALTER USER SYSDBA SET PASSWORD 'НовыйПароль' USING PLUGIN Srp;
ALTER USER SYSDBA SET PASSWORD 'НовыйПароль' USING PLUGIN Legacy_UserManager;
```

### Firebird 2.5 (утилита gsec)

В ветке Firebird 2.5 (а также в качестве легаси-способа) смена выполняется консольной утилитой `gsec`:

```bash
gsec -user sysdba -password masterkey -modify sysdba -pw НовыйПароль
```

## «Сменил пароль, а masterkey работает»: конфликт плагинов

Распространённая проблема в Firebird 3.0+ — ситуация, когда администратор изменил пароль, но старый `masterkey` продолжает подходить для авторизации.

Причина кроется в модульной системе безопасности. Начиная с Firebird 3.0, учётные записи хранятся внутри плагинов аутентификации. По умолчанию запись `SYSDBA` создаётся одновременно в двух плагинах:
* **Srp** (Secure Remote Password — современный криптографический плагин);
* **Legacy_UserManager** (для совместимости со старыми клиентами).

Смена пароля в одном плагине **не меняет** его автоматически в другом. Если вы обновили пароль через `ALTER USER SYSDBA SET PASSWORD '...'` без указания плагина, пароль обновится в плагине по умолчанию (`Srp`). Когда старый клиент подключается через протокол `Legacy_Auth`, сервер проверяет запись в `Legacy_UserManager`, где по-прежнему сохранён `masterkey`.

Чтобы полностью закрыть старый пароль, смените его для обоих плагинов:

```sql
ALTER USER SYSDBA SET PASSWORD 'НовыйПароль' USING PLUGIN Srp;
ALTER USER SYSDBA SET PASSWORD 'НовыйПароль' USING PLUGIN Legacy_UserManager;
```

## Где хранятся пользователи: файлы securityN.fdb

Все учётные данные пользователей хранятся в специальной системной базе безопасности. Её имя и структура меняются от версии к версии.

| Версия Firebird | Файл базы пользователей | Особенности хранения |
| :--- | :--- | :--- |
| **2.1 – 2.5** | `security2.fdb` | Пользователи хранятся в общей таблице `USERS`, хэш DES (8 символов) |
| **3.0** | `security3.fdb` | Появление плагинной структуры (`Srp`, `Legacy_UserManager`) |
| **4.0** | `security4.fdb` | Поддержка `Srp256`, расширенные атрибуты пользователей |
| **5.0** | `security5.fdb` | Актуальная плагинная модель хранения |

> **Обратите внимание:** при переходе на новую мажорную версию Firebird пользователи **не переносятся автоматически**, так как меняется файл базы безопасности (`securityN.fdb`). Их необходимо создавать заново или переносить скриптами.

## Что делать, если пароль утерян

Если пароль SYSDBA забыт, его нельзя восстановить в открытом виде, но можно сбросить при наличии физического доступа к серверу:

1. **В Firebird 2.5:** при наличии прав администратора ОС можно временно подменить файл `security2.fdb` чистой копией из оригинального дистрибутива (где пароль равен `masterkey`) либо воспользоваться локальным embedded-доступом через `gsec`.
2. **В Firebird 3.0+:** подключитесь к серверу локально через встроенный движок (embedded engine) под пользователем ОС с административными правами (root в Linux или Администратор в Windows). Локальное доверенное подключение не требует пароля и позволяет сразу выполнить команду `ALTER USER SYSDBA SET PASSWORD 'НовыйПароль'`. Другой вариант — замена файла `securityN.fdb` на чистый файл из архива дистрибутива.

## Безопасность: не оставляйте masterkey в проде

Пароль `masterkey` общеизвестен. Оставлять его на сервере в промышленной эксплуатации (production) — критическая уязвимость. 

Если порт Firebird (по умолчанию 3050) доступен из локальной сети или интернета, любой желающий сможет получить полный доступ к базам данных, выгрузить дампы или модифицировать записи. Меняйте стандартный пароль сразу после установки СУБД и обязательно проверяйте его смену во всех активных плагинах аутентификации.
