# Оконные функции

**Оконные (аналитические) функции** выполняют вычисления над набором строк, логически связанным с текущей записью (такой набор называется *окном*). 

Главное отличие оконных функций от классической группировки с помощью `GROUP BY` заключается в сохранении детализации:
* `GROUP BY` «схлопывает» исходные строки группы в одну результирующую строку.
* Оконная функция возвращает результат вычисления для **каждой** отдельной строки выборки, позволяя выводить агрегированные и аналитические данные вместе с детальными (неагрегированными) полями без дополнительных самосоединений (`JOIN`) и подзапросов.

Оконные функции доступны только в списке выражений `SELECT` и в предложении `ORDER BY` запроса.

> **История поддержки в Firebird:**
> * **Firebird 3.0** — реализован базовый механизм `OVER()` для стандартных агрегатных функций (`SUM`, `COUNT`, `AVG`, `MIN`, `MAX` и др.).
> * **Firebird 4.0+** — добавлены специализированные оконные функции: ранжирующие (`ROW_NUMBER`, `RANK`, `DENSE_RANK` и др.) и навигационные (`LAG`, `LEAD`, `FIRST_VALUE` и др.), а также поддержка именованных окон (`WINDOW`).

## Синтаксис OVER

Синтаксически вызов оконной функции определяется обязательным указанием предложения `OVER`, за которым следует спецификация окна в круглых скобках либо ссылка на именованное окно:

```sql
<window_function> ::=
    <aggregate_function> OVER <window_name_or_spec>
  | <window_function_name> ([<expr> [, <expr> ...]]) OVER <window_name_or_spec>

<window_name_or_spec> ::=
    <window_specification> | window_name

<window_specification> ::=
    ( [window_name] [<window partition>] [<window order>] [<window frame>] )

<window partition> ::= 
    PARTITION BY <expr> [, <expr> ...]

<window order> ::=
    ORDER BY <expr> [<direction>] [<nulls placement>]
          [, <expr> [<direction>] [<nulls placement>] ...]

<direction> ::= ASC | DESC
<nulls placement> ::= NULLS {FIRST | LAST}

<window frame> ::=
    {RANGE | ROWS} <window frame extent>

<window frame extent> ::=
    <window frame start> | <window frame between>

<window frame start> ::=
    UNBOUNDED PRECEDING | <expr> PRECEDING | CURRENT ROW

<window frame between> ::=
    BETWEEN {UNBOUNDED PRECEDING | <expr> PRECEDING | <expr> FOLLOWING | CURRENT ROW} 
        AND {UNBOUNDED FOLLOWING | <expr> PRECEDING | <expr> FOLLOWING | CURRENT ROW}
```

## Разбиение на секции (PARTITION BY)

Предложение `PARTITION BY` разделяет результирующий набор строк на независимые группы — **секции** (partitions). Вычисление оконной функции производится отдельно для каждой секции, а при переходе к следующей секции состояние функции сбрасывается.

* Если `PARTITION BY` опущен, весь результирующий набор строк запроса обрабатывается как единая секция.
* В секционировании можно указывать одно или несколько выражений: `PARTITION BY department_id, job_code`.

---

## Сортировка (ORDER BY) внутри окна

Предложение `ORDER BY` внутри `OVER(...)` задает порядок обработки строк внутри каждой секции:

* Направление сортировки: `ASC` (по умолчанию) или `DESC`.
* Расположение неопределенных значений: `NULLS FIRST` или `NULLS LAST`.
* Сортировка внутри окна определяет порядок вычисления для ранжирующих и навигационных функций, а также задает динамические границы для рамки окна.
* Сортировка в `OVER(...)` влияет исключительно на работу оконной функции и не гарантирует порядок вывода строк в финальном результате запроса (для этого по-прежнему требуется внешнее предложение `ORDER BY` на уровне самого `SELECT`).

---

## Рамка окна

**Рамка окна (window frame)** определяет подмножество строк внутри текущей секции, которые участвуют в вычислении для *текущей* строки.

Рамка задается единицей измерения (`ROWS` или `RANGE`) и границами:
* `ROWS` — физическое смещение в количестве строк относительно текущей (`N PRECEDING`, `N FOLLOWING`, `CURRENT ROW`).
* `RANGE` — логический диапазон по значениям выражения сортировки.
* Границы `UNBOUNDED PRECEDING` и `UNBOUNDED FOLLOWING` обозначают соответственно начало и конец всей секции.

**Важные правила работы рамок:**
* Использование `ROWS` или `RANGE` требует обязательного наличия `ORDER BY` внутри `OVER`.
* **Если `ORDER BY` не указан:** рамка окна охватывает **все строки секции** (от начала до конца).
* **Если `ORDER BY` указан, но рамка не задана явно:** по умолчанию применяется `RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW` (все строки от начала секции до текущей строки включительно, а также строки с равными ей значениями сортировки).

## Именованные окна

Если в запросе несколько оконных функций используют одинаковую спецификацию окна, ее можно вынести в отдельное предложение `WINDOW`, расположенное между `HAVING` и `ORDER BY`:

```sql
SELECT
    id,
    department_id,
    salary,
    AVG(salary) OVER w AS avg_dept_salary,
    SUM(salary) OVER w AS sum_dept_salary,
    ROW_NUMBER() OVER (w ORDER BY salary DESC) AS salary_rank
FROM employee
WINDOW w AS (PARTITION BY department_id);
```

Внутри `OVER(...)` можно как ссылаться на имя окна напрямую (`OVER w`), так и уточнять/расширять существующее именованное окно (`OVER (w ORDER BY ...)`).

## Список функций

Все доступные в Firebird оконные функции делятся на три группы:

| Категория | Функция | Описание |
| :--- | :--- | :--- |
| **Агрегатные функции с OVER** *(Firebird 3.0+)* | `SUM`, `COUNT`, `AVG`, `MIN`, `MAX`, `LIST` и др. | Вычисляют стандартные агрегаты по окну/секции без схлопывания строк. |
| **Ранжирующие функции** *(Firebird 4.0+)* | `ROW_NUMBER()` | Уникальный последовательный номер строки внутри секции (начиная с 1). |
| | `RANK()` | Ранг текущей строки с пропусками номеров при наличии дубликатов значений сортировки. |
| | `DENSE_RANK()` | Плотный ранг без пропусков номеров для одинаковых значений. |
| | `PERCENT_RANK()` | Относительный ранг строки (от 0.0 до 1.0). |
| | `CUME_DIST()` | Интегральное распределение: доля строк со значениями, меньшими или равными текущему. |
| | `NTILE(n)` | Разбивает секцию на `n` примерно равных групп и возвращает номер группы (от 1 до `n`). |
| **Навигационные функции** *(Firebird 4.0+)* | `LAG(expr [, offset [, default]])` | Возвращает значение `expr` из строки, отстающей на `offset` позиций назад. |
| | `LEAD(expr [, offset [, default]])` | Возвращает значение `expr` из строки, опережающей на `offset` позиций вперед. |
| | `FIRST_VALUE(expr)` | Возвращает значение `expr` первой строки в текущей рамке окна. |
| | `LAST_VALUE(expr)` | Возвращает значение `expr` последней строки в текущей рамке окна. |
| | `NTH_VALUE(expr, n)` | Возвращает значение `expr` для `n`-й строки в рамке окна (начиная с 1). |

## Пример

Рассмотрим практический пример анализа зарплат сотрудников внутри подразделений: вычисление порядкового номера, доли от общего фонда отдела, разницы с предыдущим коллегой и нарастающего итога.

```sql
SELECT
    emp_no,
    department_id,
    last_name,
    salary,
    
    -- 1. Порядковый номер сотрудника в отделе по убыванию зарплаты
    ROW_NUMBER() OVER (
        PARTITION BY department_id 
        ORDER BY salary DESC, emp_no
    ) AS rn,
    
    -- 2. Сумма зарплат по всему отделу (без сортировки = вся секция)
    SUM(salary) OVER (
        PARTITION BY department_id
    ) AS total_dept_salary,
    
    -- 3. Нарастающий итог по зарплатам внутри отдела
    SUM(salary) OVER (
        PARTITION BY department_id 
        ORDER BY salary DESC 
        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ) AS running_total,
    
    -- 4. Зарплата предыдущего сотрудника по списку (сравнение с коллегой)
    LAG(salary, 1) OVER (
        PARTITION BY department_id 
        ORDER BY salary DESC, emp_no
    ) AS prev_salary,
    
    -- 5. Разница с предыдущей зарплатой
    salary - LAG(salary, 1, salary) OVER (
        PARTITION BY department_id 
        ORDER BY salary DESC, emp_no
    ) AS salary_diff
FROM employee
ORDER BY department_id, salary DESC, emp_no;
```

| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 105 | 10 | Иванов | 120 000 | 1 | 270 000 | 120 000 | *NULL* | 0 |
| 102 | 10 | Петров | 90 000 | 2 | 270 000 | 210 000 | 120 000 | -30 000 |
| 108 | 10 | Сидоров | 60 000 | 3 | 270 000 | 270 000 | 90 000 | -30 000 |
| 201 | 20 | Ковалев | 150 000 | 1 | 250 000 | 150 000 | *NULL* | 0 |
| 204 | 20 | Смирнов | 100 000 | 2 | 250 000 | 250 000 | 150 000 | -50 000 |
