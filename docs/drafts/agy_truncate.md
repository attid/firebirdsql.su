# Как очистить таблицу в Firebird

## Короткий ответ: есть ли TRUNCATE TABLE в Firebird?

В СУБД Firebird **нет команды `TRUNCATE TABLE`**. Это принципиальная особенность архитектуры версионника (MGA): движок не умеет мгновенно обнулять указатели на страницы данных таблицы без создания версий записей.

Чтобы опустошить таблицу, используют один из трех путей:
1. Обычный `DELETE FROM tbl;` — для небольших таблиц.
2. Пакетное удаление через `EXECUTE BLOCK` порциями с фиксацией транзакций — для средних и больших таблиц.
3. Пересоздание таблицы (`DROP` / `CREATE`) — радикальный, но самый быстрый способ для сотен миллионов строк.

---

## 1. Простой случай: DELETE для небольших таблиц

Если в таблице до нескольких сотен тысяч строк, используйте стандартный SQL:

```sql
DELETE FROM my_table;
COMMIT;
```

**Что важно помнить:**
- **Запись в журнал и версионность:** Firebird создает запись об удалении (record version) для каждой строки. На огромных объемах это медленно и вызывает лавинообразный рост файла БД.
- **Генераторы:** Первичные ключи (генераторы/последовательности) автоматически **не сбрасываются**.
- **Мусор:** После массового `DELETE` страницы базы остаются заняты старыми версиями. Рекомендуется запустить сборку мусора (Garbage Collection / Sweep).

---

## 2. Сброс счетчиков (генераторов и последовательностей)

После очистки данных обычно требуется начать нумерацию ID заново.

### Firebird 3.0 и новее:
```sql
ALTER SEQUENCE gen_my_table_id RESTART WITH 0;
COMMIT;
```

### Firebird 2.5 (устаревший синтаксис):
```sql
SET GENERATOR gen_my_table_id TO 0;
COMMIT;
```
*(При следующем вызове `NEXT VALUE FOR ...` или `GEN_ID(..., 1)` вы получите значение `1`)*.

---

## 3. Быстрая очистка большой таблицы: пакетный DELETE

Удаление миллионов строк одной транзакцией заблокирует сборщик мусора, переполнит память и может повесить сервер. Правильный подход — удалять данные пачками.

Пример пакетного удаления через `EXECUTE BLOCK` порциями по 10 000 строк с использованием системного псевдо-ключа `RDB$DB_KEY`:

```sql
EXECUTE BLOCK
AS
  DECLARE VARIABLE deleted_rows INT;
BEGIN
  deleted_rows = 1;
  WHILE (deleted_rows > 0) DO
  BEGIN
    DELETE FROM my_table
    WHERE RDB$DB_KEY IN (
      SELECT RDB$DB_KEY FROM my_table ROWS 10000
    );
    deleted_rows = ROW_COUNT;
  END
END;
COMMIT;
```

*Совет:* Если удаление выполняется из внешнего скрипта (Python, C#, PHP), безопаснее удалять порции по диапазону первичного ключа (`DELETE FROM my_table WHERE id BETWEEN :start AND :end`) и делать явный `COMMIT` после каждой пачки. Это предотвратит раздувание транзакционного контекста.

## 4. Радикальный вариант: пересоздание таблицы

Когда в таблице десятки гигабайт логов или устаревших данных, самый быстрый метод — пересоздать структуру:

1. Выгрузите DDL таблицы через утилиту `isql`:
   ```bash
   isql -user SYSDBA -password masterkey -x -o table_meta.sql localhost:/path/to/db.fdb
   ```
2. Удалите старую таблицу:
   ```sql
   DROP TABLE my_table;
   COMMIT;
   ```
3. Выполните скрипт создания `CREATE TABLE`, восстановите индексы, триггеры, внешние ключи и права доступа (`GRANT`).

Этот способ отрабатывает мгновенно, но требует монопольного доступа и аккуратности с зависимыми объектами.

---

## 5. Альтернатива без пересоздания: DELETE + Sweep

Если пересоздавать структуру нельзя (много внешних зависимостей), выполните полный `DELETE`, зафиксируйте транзакцию и принудительно запустите `sweep`, чтобы освободить страницы для повторного использования:

```bash
gfix -sweep localhost:/path/to/db.fdb -user SYSDBA -password masterkey
```

## Типичные грабли при очистке

| Проблема | Причина | Как исправить |
| :--- | :--- | :--- |
| **База резко выросла в размере** | `DELETE` не сжимает файл БД на диске, а создает «мертвые» версии строк. | Выполнить `gfix -sweep`, а для физического сжатия — цикл `gbak` (backup/restore). |
| **Ошибка `violation of FOREIGN KEY`** | На таблицу ссылаются дочерние записи без `ON DELETE CASCADE`. | Сначала очистить зависимые таблицы либо временно отключить FK. |
| **Новые записи начинаются не с 1** | `DELETE` не трогает генераторы. | Явно сбросить последовательность через `ALTER SEQUENCE ... RESTART WITH 0`. |
| **Долгая транзакция подвесила БД** | Удаление миллионов строк единым монолитным запросом. | Использовать пакетный `DELETE` пачками по 5 000–50 000 строк с коммитами. |
