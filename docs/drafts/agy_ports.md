# Порты Firebird: 3050 и настройка сети

По умолчанию СУБД Firebird принимает входящие клиентские подключения по протоколу **TCP на порту 3050**. Если сервер расположен за межсетевым экраном или в изолированной подсети, для работы клиентских приложений достаточно открыть входящий порт `3050/TCP`.

---

## Таблица сетевых портов Firebird

| Порт / Протокол | Параметр в `firebird.conf` | Назначение | Особенности |
| :--- | :--- | :--- | :--- |
| **3050 / TCP** | `RemoteServicePort` | Основное подключение клиентов к СУБД | Стандартный порт сервера для передачи запросов и данных |
| **Динамический** или **фиксированный / TCP** | `RemoteAuxPort` | Вспомогательный канал для событий (`EVENT`) | Требуется только при использовании механизма подписки на события |

---

## Как изменить стандартный порт

Если порт 3050 занят другой службой или требуется запустить несколько экземпляров сервера параллельно, порт можно переопределить:

1. Откройте конфигурационный файл `firebird.conf` на сервере.
2. Найдите и раскомментируйте строку с параметром `RemoteServicePort`, указав желаемый номер:
   ```text
   RemoteServicePort = 3051
   ```
3. Перезапустите службу Firebird.

На стороне клиента при нестандартном порте измените строку подключения. Номер порта указывается через слэш после имени или IP-адреса хоста:

```text
localhost/3051:C:\databases\base.fdb
# или для Linux-путей:
192.168.1.10/3051:/var/db/base.fdb
```

## Механизм событий (EVENT) и параметр RemoteAuxPort

При использовании механизма асинхронных уведомлений (события `EVENT` / `POST_EVENT`) Firebird инициирует отдельный двусторонний канал связи между клиентом и сервером. 

По умолчанию для этого канала порт выбирается **динамически** из свободного диапазона ОС. В условиях строгих правил firewall или трансляции сетевых адресов (NAT) динамические порты блокируются, из-за чего события перестают доходить до клиентов.

Для стабильной работы событий зафиксируйте вспомогательный порт в `firebird.conf`:

```text
RemoteAuxPort = 3052
```

После перезапуска сервера откройте выбранный TCP-порт на маршрутизаторах и брандмауэрах.

## Чек-лист настройки Firewall и безопасность

При публикации сервера в локальной сети следуйте базовым правилам:

* **Разрешите входящий TCP-трафик**: откройте порт `3050` (или заданный в `RemoteServicePort`).
* **Откройте порт событий**: если приложение использует события, откройте порт из `RemoteAuxPort`.
* **Не открывайте порт 3050 наружу**: никогда не публикуйте порт СУБД в открытый интернет без VPN или SSH-туннелей во избежание атак перебором.
* **Защитите учетную запись SYSDBA**: задайте надежный, стойкий к перебору пароль для главного администратора.

## Шифрование сетевого трафика (WireCrypt)

Начиная с версии **Firebird 3.0**, сетевой протокол поддерживает встроенное шифрование передаваемых данных на базе плагина `WireCrypt`. 

Поведение шифрования регулируется в `firebird.conf`:
* `WireCrypt = Enabled` *(по умолчанию)* — шифрование используется, если поддерживается клиентом.
* `WireCrypt = Required` — сервер принудительно требует шифрование и отклоняет незашифрованные подключения.

## Диагностика и проверка соединений

### 1. Проверка доступности порта с клиента
Чтобы убедиться, что пакеты не блокируются межсетевым экраном:

* **Linux / macOS**:
  ```bash
  telnet 192.168.1.10 3050
  # или nc -zv 192.168.1.10 3050
  ```
* **Windows (PowerShell)**:
  ```powershell
  Test-NetConnection -ComputerName 192.168.1.10 -Port 3050
  ```

### 2. Проверка слушающего сокета на сервере
Убедитесь, что процесс Firebird корректно слушает порт:

```bash
netstat -tulpn | grep 3050   # Linux
netstat -ano | findstr 3050  # Windows
```

### 3. Мониторинг текущих сессий
Для просмотра активных сетевых подключений выполните SQL-запрос к системной таблице мониторинга:

```sql
SELECT 
    MON$STAT_ID, 
    MON$REMOTE_ADDRESS, 
    MON$REMOTE_PROCESS, 
    MON$TIMESTAMP 
FROM MON$CONNECTIONS;
```
