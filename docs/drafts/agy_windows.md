# Установка Firebird на Windows

Firebird — компактная, надежная и нетребовательная к системным ресурсам реляционная СУБД. Это практическое руководство поможет быстро установить Firebird на Windows, корректно сконфигурировать службу и проверить работоспособность сервера с нуля.

## Что понадобится перед стартом

Перед запуском инсталлятора подготовьте окружение и проверьте базовые требования:

- **Дистрибутив:** официальный инсталлятор загружается с сайта `firebirdsql.org` в разделе `en/downloads`.
- **Версия:** актуальная стабильная ветка — **Firebird 5.0.x**.
- **Разрядность:** доступны сборки **x64** (64-бит) и **x86** (32-бит). Для современных операционных систем и серверов выбирайте x64.
- **Сетевой порт:** по умолчанию сервер слушает порт **3050/TCP**. Убедитесь, что он не занят другими процессами.
- **Права администратора:** для корректной регистрации и запуска системной службы требуются права локального администратора.

## Пошаговая установка

1. **Запуск мастера:** скачайте установочный файл (например, `Firebird-5.0.x-windows-x64.exe`) и запустите его от имени администратора.
2. **Выбор компонентов:** инсталлятор предложит перечень устанавливаемых модулей:
   - *Сервер (Server)* — ядро СУБД.
   - *Клиент (Client)* — клиентские библиотеки.
   - *Инструменты разработчика (Developer tools)* — утилиты командной строки (`isql`, `gbak`, `gfix` и др.).
   - *Документация (Documentation)*.
   *(Примечание: если машина будет выступать только рабочим местом для подключения к удаленной базе, выберите вариант **Client only** — установятся исключительно библиотеки клиента без серверного движка).*
3. **Параметры службы:** оставьте вариант развертывания в качестве службы Windows с именем **Firebird Server** и автоматическим типом запуска.
4. **Пароль SYSDBA:** на этапе настройки безопасности задайте надежный пароль для главного администратора СУБД (`SYSDBA`) и сохраните его.
5. **Завершение:** подтвердите настройки, выполните установку и закройте мастер.

## Проверка работоспособности

Убедитесь, что сервер успешно стартовал и готов принимать входящие подключения:

1. **Проверка службы:** нажмите `Win + R`, введите `services.msc` и найдите в списке службу **Firebird Server**. Ее статус должен быть «Выполняется» (*Running*).
2. **Консольная проверка через ISQL:** откройте командную строку и выполните подключение к тестовой базе `employee`:
   ```cmd
   isql localhost/3050:employee -user sysdba -password <ваш_пароль>
   ```
   Появление приглашения командной строки `SQL>` означает, что сетевой стек и движок СУБД работают штатно.
3. **GUI-клиенты:** проверить связь можно также через графические инструменты администрирования (DBeaver, FlameRobin, IBExpert), указав хост `localhost`, порт `3050`, пользователя `SYSDBA` и заданный пароль.

## Типичные грабли при установке

| Проблема | Причина | Решение |
| :--- | :--- | :--- |
| **Порт 3050 уже занят** | В системе уже запущен другой экземпляр Firebird или Borland InterBase. | Остановите конфликтующую службу или переназначьте порт в `firebird.conf`. |
| **Конфликт разрядности (x86 vs x64)** | 32-битное приложение не может загрузить 64-битную `fbclient.dll` (или наоборот). | Установите клиентскую библиотеку той же битности, что и вызывающее ПО. |
| **Ошибки доступа в Program Files** | Защита UAC и ограничения прав NTFS при создании баз в системной папке. | Храните файлы баз данных (`.fdb`) в отдельном каталоге с правами на запись для службы. |
| **Нет удаленного доступа по сети** | Сетевой порт заблокирован системным брандмауэром. | Добавьте входящее правило для порта `3050/TCP` в Windows Firewall. |

## Вариант Firebird Embedded

Если вам не нужен полноценный сервер, а требуется локальная СУБД внутри одного приложения, используйте **Firebird Embedded**. 

Этот вариант поставляется в виде отдельного **ZIP-архива** (не инсталлятором). Он не требует прав администратора и не создает службу Windows. Библиотеки просто распаковываются в каталог рядом с исполняемым файлом вашей программы, а доступ к файлу базы данных осуществляется напрямую в монопольном режиме.

## Что делать дальше

Первым делом после успешной инсталляции сервера настройте регулярный бэкап. В Firebird для этого используется штатная утилита **gbak**, позволяющая создавать целостные резервные копии «на лету» без остановки работы пользователей.

**Что почитать дальше:**
- Настройка и оптимизация параметров в `firebird.conf`
- Управление пользователями, ролями и правами доступа
- Автоматизация создания резервных копий с помощью `gbak`
- Диагностика и восстановление баз данных утилитой `gfix`
