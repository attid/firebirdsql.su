# Триггеры в Firebird: типы, события, NEW/OLD

Триггер в Firebird — это компилируемый блок процедурного языка (PSQL), который СУБД автоматически запускает при наступлении определённого события. Триггеры поддерживаются во всех версиях Firebird (2.5–6.0) и используются для валидации данных, генерации первичных ключей, ведения аудита, поддержания сложных ограничений целостности и логирования системных действий.

В отличие от некоторых других СУБД, в Firebird на одну таблицу и событие можно назначать несколько триггеров. Порядок их исполнения задаётся директивой `POSITION <число>` (триггеры с меньшим номером срабатывают раньше).

## DML-триггеры: события, NEW/OLD и предикаты

DML-триггеры привязываются к таблицам или представлениям (views) и срабатывают на события `INSERT`, `UPDATE`, `DELETE` в фазах:
- **`BEFORE`** — до физической записи на диск. Позволяет модифицировать поля через переменные `NEW.xxx` или отменить действие, выбросив исключение.
- **`AFTER`** — после применения операции. Значения уже зафиксированы в контексте таблицы; часто используется для каскадных обновлений и аудита.

Триггеры для представлений превращают необновляемые представления в обновляемые (updatable views), перехватывая манипуляции с данными.

### Контекстные переменные NEW и OLD
- **`NEW`** — содержит новые значения колонок. Доступна в `INSERT` и `UPDATE`. В `BEFORE`-триггерах поля `NEW` можно перезаписывать (`NEW.MODIFIED_AT = CURRENT_TIMESTAMP;`). В операциях `DELETE` переменная недоступна.
- **`OLD`** — содержит значения до изменения. Доступна в `UPDATE` и `DELETE`. Поля `OLD` доступны только для чтения. При `INSERT` обращение к `OLD` вызывает ошибку.

### Мульти-события и булевы флаги
Объединение событий через `OR` (например, `BEFORE INSERT OR UPDATE`) и предикаты `INSERTING`, `UPDATING`, `DELETING` поддерживаются начиная с версии Firebird 1.5 (соответственно, работают и в 2.5, и в 3.0+). Они позволяют сгруппировать логику в одном месте.

```sql
SET TERM ^ ;
CREATE OR ALTER TRIGGER TR_EMPLOYEE_AUDIT FOR EMPLOYEE
ACTIVE AFTER UPDATE POSITION 10
AS
BEGIN
  IF (OLD.SALARY IS DISTINCT FROM NEW.SALARY) THEN
  BEGIN
    INSERT INTO SALARY_HISTORY (EMP_ID, OLD_VAL, NEW_VAL, CHG_USER, CHG_TIME)
    VALUES (NEW.ID, OLD.SALARY, NEW.SALARY, CURRENT_USER, CURRENT_TIMESTAMP);
  END
END^
SET TERM ; ^
```

## Триггеры событий базы данных (2.1+)

Появились в Firebird 2.1. Срабатывают на глобальные события сессий и транзакций, не привязаны к конкретным таблицам:
- **`ON CONNECT`** / **`ON DISCONNECT`** — при подключении/отключении пользователя (удобно для проверки прав, настройки сессионного контекста или записи в журнал).
- **`ON TRANSACTION START`** / **`COMMIT`** / **`ROLLBACK`** — при начале, успешном завершении или откате транзакции.

## DDL-триггеры (3.0+)

Начиная с Firebird 3.0 доступны DDL-триггеры (`BEFORE DDL` / `AFTER DDL`). Они срабатывают при выполнении выражений изменения схемы: `CREATE`, `ALTER` и `DROP` для таблиц, индексов, процедур, пользователей и других объектов. Служат для защиты схемы от несанкционированных изменений и репликации метаданных.

## Ограничения и грабли

1. **Запрет `COMMIT` и `ROLLBACK`**: в процедурном коде PSQL явные транзакционные операторы синтаксически запрещены. Триггер выполняется строго внутри транзакции вызвавшего его стейтмента. Для отмены операции вызывается оператор `EXCEPTION`. Если необходимо сохранить запись независимо от исхода родительской транзакции (например, журнал ошибок), используют блок `IN AUTONOMOUS TRANSACTION DO` (доступен с 2.5).
2. **Системные таблицы**: метаданные триггеров хранятся в `RDB$TRIGGERS`, а связанные тексты пользовательских ошибок — в `RDB$TRIGGER_MESSAGES`.
3. **Рекурсия**: если `AFTER UPDATE` триггер обновляет ту же таблицу, возможен бесконечный цикл. Firebird имеет лимит глубины вложенности стека (до 1000 уровней), после чего прерывает выполнение с ошибкой.

## Сводная таблица: типы триггеров Firebird

| Тип триггера | Версии Firebird | События | Фазы | Целевой объект |
| :--- | :--- | :--- | :--- | :--- |
| **DML** | 2.5–6.0 *(мульти-события с 1.5)* | `INSERT`, `UPDATE`, `DELETE` | `BEFORE`, `AFTER` | Таблицы, представления (Views) |
| **Database** | 2.1–6.0 | `CONNECT`, `DISCONNECT`, `TRANSACTION START/COMMIT/ROLLBACK` | Момент наступления события | База данных |
| **DDL** | 3.0–6.0 | `CREATE/ALTER/DROP <OBJECT>`, `ANY DDL STATEMENT` | `BEFORE`, `AFTER` | Метаданные БД |
