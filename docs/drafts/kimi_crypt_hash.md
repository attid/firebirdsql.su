• # CRYPT_HASH

  ## Доступно в

  DSQL, PSQL

  ## Формат

  ```
  CRYPT_HASH (value USING <algorithm>)

  <algorithm> ::= { MD5 | SHA1 | SHA256 | SHA512 | SHA3_224 | SHA3_256 | SHA3_384 | SHA3_512 }
  ```

  ## Описание

  Функция `CRYPT_HASH` вычисляет криптографический хэш от входного значения и возвращает результат типа `VARBINARY`. Алгоритм хеширования задаётся предложением `USING` и выбирается из списка: `MD5`, `SHA1`, `SHA256`, `SHA512`, `SHA3_224`, `SHA3_256`, `SHA3_384`, `SHA3_512`.

  Параметр `value` может быть выражением любого типа. Не строковые и не бинарные типы данных перед хешированием автоматически приводятся к строке. Функция полностью поддерживает текстовые `BLOB` любой длины и с любым набором символов, поэтому её можно применять к документам и другим крупным текстовым значениям без ограничений по размеру.

  Важно учитывать, что алгоритмы `MD5` и `SHA1` не рекомендуются к использованию: для них известны серьёзные проблемы стойкости. Они сохранены в функции *только* ради обратной совместимости со старым кодом. Для новых разработок следует выбирать `SHA256`, `SHA512` или один из алгоритмов семейства `SHA3`.

  Типичные применения: контроль целостности данных, сравнение содержимого полей без передачи самого содержимого, построение детерминированных ключей дедупликации.

  ## Пример

  ```sql
  -- Хэш значения поля по алгоритму SHA256, результат типа VARBINARY
  SELECT CRYPT_HASH(x USING SHA256)
  FROM MyTable;

  -- Проверка целостности документа: сравнение текущего хэша BLOB с сохранённым
  SELECT id
  FROM documents
  WHERE CRYPT_HASH(body USING SHA512) <> saved_hash;
  ```
