# gstat: статистика базы данных Firebird

Если запросы к Firebird внезапно замедлились, оптимизатор строит неоптимальные планы, а файл базы стремительно увеличивается в размерах — скорее всего, база страдает от раздувания (bloat) версиями записей или деградации индексов. Разобраться с происходящим помогает **gstat** — штатная консольная утилита Firebird.

Она анализирует базу данных на уровне физических страниц и предоставляет детальную диагностику: занятое и свободное пространство, цепочки версий записей (record versions) и структуру индексных деревьев.

---

### Где лежит и как запускать

Утилита входит в стандартную поставку СУБД:
* **Linux:** `/opt/firebird/bin/gstat`
* **Windows:** `bin\gstat` внутри каталога установки Firebird

**Требования к запуску:**
* Обязательно указывается файл базы данных (или алиас).
* Требуются права администратора базы данных.
* Утилита штатно работает при запущенном сервере.

Синтаксис локального подключения:
```bash
gstat -u SYSDBA -p masterkey /var/db/production.fdb
```

---

### Основные режимы работы (ключи)

| Ключ | Режим | Назначение |
|---|---|---|
| `gstat -h база` | **Header** | Заголовок базы: версия ODS, размер страницы (page size), sweep interval, счетчики транзакций и системные лимиты. |
| `gstat -d база` | **Data** | Страницы данных: средние размеры записей, цепочки и количество версий. |
| `gstat -i база` | **Index** | Состояние индексов: глубина дерева (depth), селективность, дубликаты, заполненность страниц. |
| `gstat -t TABLE1 TABLE2 база` | **Tables** | Анализ только указанных таблиц (регистр имени таблицы важен!). |
| `gstat -a база` | **All** | Полный отчет по всей базе: заголовок, все таблицы и все индексы. |

### Как читать вывод gstat

#### 1. Заголовок базы (`-h`)
```text
Database header page information:
    ODS version             12.2
    Page size               8192
    Oldest transaction      140231
    Oldest active           140232
    Oldest snapshot         140232
    Next transaction        189420
    Sweep interval          20000
```
Следите за разрывом между `Oldest transaction` и `Next transaction`. Если разрыв исчисляется миллионами, в базе зависли «старые» открытые транзакции, блокирующие сборку мусора.

#### 2. Страницы данных (`-d` или `-t`)
```text
DOCUMENTS (128)
    Primary pointer page: 540, Index root page: 541
    Average record length: 142.30, total records: 1250040
    Average version length: 98.15, total versions: 3420890, max versions: 42
```
* **Average record length / Average version length** — средний размер полезных данных и дельт версий.
* **total versions** и **max versions** — критичный показатель. Если число версий в разы превышает `total records`, в таблице скопился огромный хвост недособранного мусора из-за долгих снимков или частых `UPDATE`/`DELETE`.

#### 3. Страницы индексов (`-i` или `-t`)
```text
Index IDX_DOC_DATE (0)
    Depth: 4, leaf buckets: 1820, nodes: 1250040
    Average data length: 4.12, total dup: 42010
    Fill distribution:
         0 - 19% = 0
        20 - 39% = 18
        40 - 59% = 340
        60 - 79% = 890
        80 - 99% = 572
```
* **Depth (глубина индекса):** 1–3 — штатное значение. Значение 4 и выше сигнализирует о разрастании B-дерева; такой индекс пора дефрагментировать/перестроить.
* **Fill distribution:** если большинство страниц заполнены менее чем на 50%, индекс разрежен и занимает лишний кэш.

### Грабли и подводные камни

1. **gstat — только градусник:** утилита проводит диагностику, но сама ничего не удаляет и не чистит. Очистка версий выполняется фоновым процессом sweep (`gfix -sweep база`) либо обычными транзакциями при чтении данных.
2. **Нагрузка от ключа `-a`:** на больших базах запуск `gstat -a` считывает гигабайты страниц, вытесняя рабочий кэш и создавая тяжелый дисковый I/O. На продакшене анализируйте точечно: `gstat -t TABLE_NAME база`.
3. **Несовпадение ODS:** версия утилиты `gstat` должна строго соответствовать версии структуры базы данных (ODS). Например, `gstat` от Firebird 2.5 не откроет базу Firebird 5.0.
4. **Регистр в `-t`:** имена таблиц чувствительны к регистру. Если таблицы создавались без явных двойных кавычек, их имена хранятся в верхнем регистре (`gstat -t MY_TABLE база`).

### Альтернативы с GUI

Для визуализации дерева индексов и распределения версий без парсинга текстовых логов:
* **IBAnalyst** — классический инструмент глубокого анализа отчетов `gstat`.
* **HQbird мониторинг** — комплексный мониторинг состояния и аудита производительности Firebird.

---

### Что изучить дальше

После устранения аномалий обязательно повторите запуск `gstat`, чтобы оценить результат очистки. Связанные темы для изучения:
* Очистка мусора и запуск sweep через утилиту **gfix**.
* Восстановление и дефрагментация базы через резервное копирование **gbak**.
* Быстрые инкрементальные копии утилитой **nbackup**.
* Оперативный онлайн-мониторинг блокировок и долгих транзакций через **системные таблицы `MON$`**.
