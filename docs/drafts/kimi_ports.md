• # Порты Firebird: 3050 и настройка сети

  **Короткий ответ:** сервер Firebird по умолчанию слушает TCP-порт **3050**. Именно его нужно пробросить в firewall, чтобы клиенты могли подключаться к базе по сети. Порт задаётся параметром `RemoteServicePort` в файле `firebird.conf` и указывается в строке подключения явно, если он отличается от стандартного.

  ## Таблица портов Firebird

  | Назначение | Порт | Протокол | Параметр в firebird.conf |
  |---|---|---|---|
  | Основное подключение клиентов | 3050 | TCP | `RemoteServicePort` |
  | События (EVENT) | динамический, если не задан явно | TCP | `RemoteAuxPort` |

  ## Как сменить порт

  Порт меняется на стороне сервера — в файле `firebird.conf`:

  ```
  RemoteServicePort = 3051
  ```

  После правки сервер нужно перезапустить, чтобы параметр подхватился. На клиентах новый порт указывается в строке подключения через слэш после имени хоста:

  ```
  localhost/3051:base.fdb
  ```

  Соответственно, если порт нестандартный, строку подключения придётся поправить у всех клиентов и в конфигах приложений — иначе они продолжат стучаться на 3050.

  ## События и RemoteAuxPort

  Отдельная история — события Firebird (EVENT). Для них сервер открывает **дополнительное соединение**. Если параметр `RemoteAuxPort` в `firebird.conf` не задан, порт для событий выбирается динамически — и строгий firewall или NAT такое соединение режет, потому что заранее неизвестно, какой порт открывать.

  Решение простое: зафиксировать порт явно.

  ```
  RemoteAuxPort = 3060
  ```

  После этого открываете в firewall оба порта — 3050 и выбранный вами порт событий — и события начинают работать через NAT без сюрпризов.

  ## Firewall: чеклист

  - Открыть входящий TCP 3050 (или ваш кастомный `RemoteServicePort`) на сервере.
  - Если используются события — задать `RemoteAuxPort` и открыть его тоже.
  - Ограничить доступ по IP, если база нужна только определённым подсетям или хостам.
  - **Не выставлять 3050 в интернет без крайней необходимости.** Если удалённый доступ всё-таки нужен — хотя бы VPN или туннель.
  - Убедиться, что у SYSDBA сильный пароль: открытый порт плюс заводской `masterkey` — классическая находка для сканеров.

  ## Шифрование канала

  С Firebird 3.0 трафик между клиентом и сервером шифруется на уровне wire-протокола. За это отвечает параметр `WireCrypt` в `firebird.conf`. По умолчанию он стоит в `Enabled` — шифрование используется, если клиент его поддерживает. Если хотите запретить незашифрованные подключения вовсе, выставьте:

  ```
  WireCrypt = Required
  ```

  Это особенно важно, когда база доступна за пределами доверенного сегмента сети.

  ## Проверка доступности и соединений

  Быстрая проверка «с клиента доходит ли до сервера»:

  ```
  telnet host 3050
  ```

  В Windows вместо telnet удобнее PowerShell:

  ```powershell
  Test-NetConnection host -Port 3050
  ```

  На самом сервере убедиться, что процесс слушает порт, поможет `netstat` — в выводе должен быть 3050 (или ваш порт) в состоянии LISTENING.

  Кто именно подключён к базе прямо сейчас, видно через системные таблицы мониторинга — в первую очередь `MON$CONNECTIONS`. Там есть адреса клиентов, пользователи и время подключения — удобно и для диагностики, и для контроля, кто ходит в базу по сети.
