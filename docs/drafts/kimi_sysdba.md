# SYSDBA в Firebird: пароль по умолчанию и как его сменить

## Кто такой SYSDBA

SYSDBA (System Database Administrator) — встроенный суперпользователь Firebird. Он существует во всех версиях сервера, от 2.5 до 6.0, и имеет полный доступ ко всем базам данных на сервере, минуя проверки прав внутри самих баз.

Важно: SYSDBA — это именно пользователь, а не роль. Его не следует путать с ролью RDB$ADMIN, которая существует внутри отдельных баз данных и даёт права администратора только в конкретной базе.

## Пароль по умолчанию

Классический пароль SYSDBA — `masterkey`. При этом значимы только первые 8 символов пароля, поэтому `masterke` тоже сработает.

Однако `masterkey` вы получите не всегда — многое зависит от способа установки:

- **Windows-инсталлятор** при установке спрашивает пароль SYSDBA. Если вы обновляете сервер поверх старой установки, пароль может остаться прежним — тем, что был задан раньше.
- **Установка из архива на Linux**: пароль генерируется автоматически в процессе установки и сохраняется в файл `SYSDBA.password` в корневом каталоге установки Firebird (обычно `/opt/firebird/`, рядом с базой безопасности).

Поэтому, если `masterkey` не подходит, первым делом проверьте, не задан ли пароль при установке.

## Как сменить пароль SYSDBA

### Firebird 3.0 и новее — через SQL

Подключитесь к любой базе от имени SYSDBA и выполните:

```sql
ALTER USER SYSDBA SET PASSWORD 'новый_пароль';
```

Опционально можно указать плагин аутентификации явно:

```sql
ALTER USER SYSDBA SET PASSWORD 'новый_пароль' USING PLUGIN Srp;
ALTER USER SYSDBA SET PASSWORD 'новый_пароль' USING PLUGIN Legacy_UserManager;
```

### Firebird 2.5 — через gsec

В 2.5 (а также как легаси-путь в более новых версиях) пароль меняется утилитой gsec:

```
gsec -user sysdba -password masterkey -modify sysdba -pw новый_пароль
```

## Сменил пароль, а masterkey всё равно работает

Это самая частая ловушка Firebird 3.0+. Начиная с версии 3.0, учётные записи хранятся не в одном месте, а в плагинах аутентификации. Пользователь SYSDBA обычно существует сразу в двух плагинах: `Srp` и `Legacy_UserManager`.

Ключевое следствие: смена пароля в одном плагине **не меняет** его в другом. Если вы выполнили `ALTER USER ... USING PLUGIN Srp`, то в `Legacy_UserManager` у SYSDBA остался старый пароль — например, тот самый `masterkey`. Сервер, в зависимости от настроек, может пускать через любой из плагинов, и «неубитый» пароль продолжает работать.

Лечение: меняйте пароль в обоих плагинах — два оператора `ALTER USER` с явным `USING PLUGIN`, как показано выше.

## Где хранятся пользователи

Учётные записи живут в отдельной служебной базе — базе безопасности. Её имя зависит от версии сервера:

| Версия Firebird | Файл базы безопасности |
|---|---|
| 2.1–2.5 | security2.fdb |
| 3.0 | security3.fdb |
| 4.0 | security4.fdb |
| 5.0 | security5.fdb |

Важный нюанс: при обновлении версии сервера пользователи **не переносятся автоматически**. После миграции, скажем, с 2.5 на 4.0 база security4.fdb будет содержать свежего SYSDBA с паролем, заданным при установке, а все ваши старые учётки останутся в security2.fdb.

## Потерян пароль SYSDBA — что делать

Отдельной команды «сбросить пароль» в Firebird нет: пароль хранится в базе безопасности в хешированном виде, и подсмотреть его нельзя. Практические варианты:

- Проверьте файл `SYSDBA.password` (установка из архива на Linux) — вдруг пароль там.
- Если есть другой пользователь с правами администратора базы безопасности, смените пароль SYSDBA от его имени.
- В крайнем случае — переустановка сервера или замена базы безопасности «чистой» с последующим пересозданием пользователей. Учтите: пользовательские базы данных при этом не пострадают, но все учётные записи придётся заводить заново.

## Безопасность

Пароль `masterkey` известен всему интернету. Оставлять его на сервере, доступном хоть кому-то кроме вас, — значит отдать ключи от всех баз сразу. Минимум после установки:

- смените пароль SYSDBA (в 3.0+ — во всех плагинах аутентификации);
- не используйте SYSDBA для повседневной работы приложений — заведите отдельных пользователей с нужными правами;
- следите за файлом `SYSDBA.password` на Linux: пароль там лежит в открытом виде.
