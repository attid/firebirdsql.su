• # ROLLBACK

  ## Доступно в

  DSQL, ESQL

  ## Формат

  ```
  ROLLBACK [WORK] [TRANSACTION tr_name]
    [RETAIN [SNAPSHOT] | TO SAVEPOINT sp_name] [RELEASE];
  ```

  **Параметры оператора ROLLBACK**

  | Параметр | Описание |
  |---|---|
  | tr_name | Имя транзакции. Доступно только в ESQL. |
  | sp_name | Имя точки сохранения. Доступно только в DSQL. |

  ## Описание

  Оператор `ROLLBACK` отменяет все изменения данных базы данных (добавление, изменение, удаление), выполненные в контексте транзакции. Оператор никогда не вызывает ошибок. Если не указано предложение `RETAIN`, при его выполнении освобождаются все ресурсы сервера, связанные с данной транзакцией.

  Необязательное предложение `TRANSACTION` задаёт имя транзакции и доступно только в Embedded SQL. За счёт именованных транзакций допускается одновременный запуск нескольких активных транзакций в одном приложении; при этом должна быть объявлена и инициализирована одноимённая переменная базового языка. В DSQL это ограничение предотвращает динамическую спецификацию имён транзакций. Если `TRANSACTION` не указано, оператор применяется к транзакции по умолчанию. Ключевое слово `WORK` используется лишь для совместимости с другими СУБД.

  Ключевое слово `RETAIN` указывает, что все изменения данных отменяются, а транзакция остаётся активной, сохраняя свой идентификатор и состояние курсоров. Для уровней изоляции `SNAPSHOT` и `SNAPSHOT TABLE STABILITY` вид базы данных остаётся таким, каким он был при старте транзакции; для `READ COMMITTED` база принимает вид, соответствующий новому состоянию на момент выполнения `ROLLBACK RETAIN`. При откате с сохранением контекста заново выполнять `SELECT` не требуется.

  ### ROLLBACK TO SAVEPOINT

  Предложение `TO SAVEPOINT` задаёт имя точки сохранения, на которую выполняется откат. Отменяются все изменения, начиная с созданной точки сохранения; пользовательские переменные, заданные функцией `RDB$SET_CONTEXT()`, остаются неизменными. Все точки сохранения, созданные после названной, уничтожаются; сама точка и более ранние остаются, поэтому откатываться к одной и той же точке можно несколько раз. Все явные и неявные блокировки записей, установленные начиная с точки сохранения, освобождаются.

  ## Пример

  Полный откат транзакции:

  ```sql
  UPDATE employees SET salary = salary * 1.1 WHERE dept_no = 600;
  -- решение изменено: отменяем обновление
  ROLLBACK;
  ```

  Частичный откат к точке сохранения:

  ```sql
  INSERT INTO orders (order_id, customer_id) VALUES (1001, 15);
  SAVEPOINT before_details;

  INSERT INTO order_details (order_id, product_id, qty) VALUES (1001, 220, 3);
  -- ошибка в данных деталей: откатываемся к точке сохранения,
  -- сама вставка заказа сохраняется
  ROLLBACK TO SAVEPOINT before_details;

  INSERT INTO order_details (order_id, product_id, qty) VALUES (1001, 221, 2);
  COMMIT;
  ```
