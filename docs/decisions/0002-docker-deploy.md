# ADR-0002: Деплой в Docker на собственном сервере

Статус: принято (владелец: «сейчас это докер у меня на сервере, так и будет докер»).

## Контекст

Старая вики уже работает в Docker на сервере владельца. Старые URL из поисковой
выдачи построены на `/doku.php?id=<page_id>` — для 301 с query-string нужен
собственный nginx; GitHub Pages это не умеет, Cloudflare Pages потребовал бы
отдельный Worker.

## Решение

Новый сайт — Docker-контейнер (nginx + собранная статика) на том же сервере,
deploy через docker compose. Карта 301 со старых URL живёт в конфиге этого
nginx. Старый контейнер вики остаётся до подтверждения переключения; откат —
возврат upstream.

## Альтернативы

- **Cloudflare Pages + Worker**: бесплатный CDN, но Worker для query-редиректов —
  лишняя движущаяся деталь в самом критичном для SEO месте.
- **GitHub Pages**: редиректы с query-string невозможны в принципе.

## Последствия

- Полное покрытие старых URL редиректами (обе формы: `/doku.php?id=...` и `/<page_id>`).
- Ноль новых внешних сервисов и зависимостей.
- CI/CD при желании сводится к `docker build && docker compose up -d` на сервере.
