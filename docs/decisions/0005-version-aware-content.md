# ADR-0005: Версионная осведомлённость контента (фильтр по версии Firebird)

Статус: принято (идея владельца; паттерн — MDN Browser Compatibility Data).

## Контекст

Пользователь сайта работает на конкретной версии Firebird (2.5 / 3.0 / 4.0 / 5.x)
и не хочет видеть конструкции, которые на его версии ещё не появились или уже
не работают. Эталонный UX — MDN: структурированные метаданные совместимости
в данных, из которых рендерятся таблицы и фильтры.

## Решение

1. Контентная схема (frontmatter каждой страницы глоссария) с самого начала
   включает поля версий:
   - `firebird.since` — версия, в которой конструкция появилась;
   - `firebird.until` — версия, в которой перестала работать (если да);
   - `firebird.deprecated` — признак устаревания.
   Конвертер (этап 1) создаёт поля пустыми — они часть схемы, удалять нельзя.
2. Данные версий проставляются на этапе контент-апгрейда (этап 4) по официальному
   Language Reference и release notes Firebird.
3. UI: переключатель «Моя версия» в шапке (2.5 / 3.0 / 4.0 / 5.x), выбор
   хранится в localStorage; конструкции вне версии либо скрываются, либо
   помечаются бейджем «с 3.0» / «удалено в 5.0» — финальное поведение
   уточняется на реальных данных.

## Последствия

- Схема URL и структура контента не зависят от версий — фильтр чисто
  надстроечный, ничего не ломает при откладывании.
- Простановка версий — большая контентная работа, отдельный конвейер
  (можно прогонять итеративно, по разделам глоссария).
- SEO-бонус: страницы с честными бейджами версий лучше отвечают на запросы
  вида «merge firebird 2.5».
