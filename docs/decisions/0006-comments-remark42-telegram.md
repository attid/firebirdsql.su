# ADR-0006: Комментарии — remark42, авторизация Telegram + Яндекс + Google

Статус: принято (владелец: «авторизацию через тг хочу, потом другие»;
OAuth Яндекса и Google добавлены решением владельца сразу).

## Контекст

Сайт статический, но нужны комментарии. Аудитория — русскоязычные разработчики
1С/Firebird, GitHub-аккаунт есть не у всех. Владелец уже эксплуатирует Docker,
лишний контейнер приемлем. Отдельную полноценную систему регистрации не хотим.

## Решение

remark42 (self-hosted, свой контейнер в том же compose):

- включённые провайдеры авторизации:
  - Telegram (`AUTH_TELEGRAM=true`, `TELEGRAM_TOKEN` — токен бота
    от @BotFather);
  - Яндекс (`AUTH_YANDEX=true` + ключи приложения Яндекс.OAuth);
  - Google (`AUTH_GOOGLE=true` + OAuth-клиент Google Cloud Console;
    для внешних пользователей без верификации приложения Google показывает
    предупреждение «непроверенное приложение» — терпимо для старта,
    верификация по желанию позже);
- прочие провайдеры remark42 (GitHub, Apple, email, аноним) включаются
  точечно по мере надобности; мессенджеров, кроме Telegram, у remark42 нет —
  это ограничение движка, зафиксировано честно;
- данные комментариев — в volume контейнера, включаются в бэкап сервера;
- модерация — штатная админка remark42.

Против ДДос/спама: rate limiting на nginx перед remark42 (см. deploy/README.md),
штатные лимиты remark42, ограничение размеров и частоты сообщений.

## Альтернативы

- **giscus (GitHub Discussions)** — ноль инфраструктуры, но требует
  GitHub-аккаунт: отсекает большую часть аудитории.
- **Disqus и внешний хостинг** — трекеры, реклама, чужие данные; не подходит.

## Последствия

- Один контейнер и один volume дополнительно; бэкап замечает ещё один путь.
- Виджет подключается на статических страницах как остров — генератору
  всё равно, Astro это покрывает.
