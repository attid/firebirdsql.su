# ADR-0001: Переезд с DokuWiki на статический сайт в git

Статус: принято (владелец подтвердил: движок меняем, правки сообщества — через git).

## Контекст

firebirdsql.su — DokuWiki (PHP 8.4, nginx) с ~215 страницами. Дефолтный шаблон,
кэширования для анонимов нет, robots.txt и sitemap.xml отсутствуют (отдают
soft-404), canonical указывает на http://. Активность редакторов в последние
полгода близка к нулю, потребности в правках через браузер нет. Главное
ограничение — сохранить SEO: многие страницы в поисковой выдаче.

## Решение

Переносим контент в git и собираем сайт статическим генератором. DokuWiki
остаётся источником для разового снятия контента (`do=export_raw`), после
миграции — read-only архив. Правки контента — pull request'ами.

## Альтернативы

- **Остаться на DokuWiki** (новый шаблон, плагины, кэш nginx): дешевле на старте,
  но контент по-прежнему вне git, скорость и SEO-инфраструктура ограничены
  возможностями движка.
- **Гибрид** (wiki как CMS + статический экспорт): два движущихся элемента вместо
  одного, сложнее поддержка при почти нулевой активности редакторов.

## Последствия

- Один раз платим за конвертер DokuWiki → Markdown; дальше контент в Markdown.
- Полный контроль над URL, мета-тегами, скоростью, редиректами.
- Нужна дисциплина карты редиректов (см. docs/seo-migration.md, AGENTS.md).
- История правок DokuWiki не переносится в git-историю; снимок сохраняем в legacy/.
